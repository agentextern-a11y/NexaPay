Key Architectural Principle: The Platform Never Holds Keys

The user signs transactions client-side. The platform:

· Indexes blockchain state (read-only wallet service)
· Facilitates conversion quotes
· Manages card lifecycle with issuer
· Records ledger entries
· Enforces compliance rules

But never custodies assets or holds private keys.

06 | NON-CUSTODIAL PAYMENT FLOW (REVISED)

```
1. User taps phone at merchant terminal (NFC)
2. Terminal sends authorization request via card network
3. Card network routes to issuer (Marqeta)
4. Issuer sends webhook to Nexa Pay: "Auth request for Card X, Amount Y"
5. Nexa Pay checks:
   a. User's indexed Base L2 balance (read-only)
   b. OPM token balance (for fee waiver)
   c. Risk score / compliance flags
6. Nexa Pay returns APPROVE/DECLINE to issuer
   ─── NO CRYPTO MOVES YET ───
7. If APPROVED, Nexa Pay generates a transaction payload
8. User's device signs the transaction (biometric confirmation)
9. USDC transfers from user's wallet → liquidity pool → settlement
10. Ledger records: DEBIT user_wallet, CREDIT settlement_account
11. Settlement completes via card network rails (1-2 days)
12. Merchant receives fiat
```

Critical insight: The authorization (step 2-6) happens in <800ms. The actual crypto settlement (steps 7-10) can take 1-2 seconds on Base L2. This matches your site's "under 2 seconds" claim for settlement while maintaining <800ms for the auth-critical path.
